## D-020: List supported agents alphabetically, with no "not ranked" disclaimer

- **Status**: accepted
- **Date**: 2026-07-08
- **Context**: The agent-name chips (D-019) and the doc table both need a listing
  order. With a functional-parity claim (project D-030), any fixed order can be
  read as a covert ranking, and the agents are currently listed Claude-Code-first
  on every surface. The project-level CI guard (project T-050) will assert these
  support strings, so the order also needs to be stable and reproducible, not
  randomized per build.
- **Decision**: List agents alphabetically — Claude Code, Codex CLI, opencode —
  and add no explicit "this isn't a ranking" disclaimer.
- **Rationale**: Alphabetical is neutral and self-explanatory ("it's
  alphabetical, not a tier"), stable for the CI guard, and equals today's order
  so it introduces zero churn. An explicit anti-ranking note was rejected as
  protesting-too-much — a disclaimer draws attention to a hierarchy nobody asked
  about, and an obviously-alphabetical list needs no defense. Dogfood-first
  ordering (Claude Code first because it is the daily-driver environment) was
  rejected because it reintroduces the exact primacy signal project D-030
  removes; validation-date order was rejected as arbitrary to a visitor and
  unstable as the list grows.
