## D-002: Build the site as Next.js on Vercel with a live server runtime, not a static export

- **Status**: accepted
- **Date**: 2026-07-05
- **Context**: The site needs a marketing landing page plus detailed docs. Initially framed as static/no-backend, but the owner wants dynamic functionality (contact form, newsletter signup), which requires server-side handling.
- **Decision**: Build the site with Next.js (App Router) deployed on Vercel, using its serverless/server runtime for form-handling API routes. This explicitly rejects the earlier static, no-backend, no-user-data premise.
- **Rationale**: Contact and newsletter forms need server endpoints to validate input and call third-party providers with secret API keys; a pure static export cannot hold secrets or POST safely. Next.js + Vercel gives first-class DX, per-PR preview deploys, and a runtime for the form endpoints. Cost accepted: a Vercel vendor account and its env-secret surface, versus the project's otherwise everything-in-repo minimalism.
- **Note**: Invalidates the working "static / no-backend / no user data" premise. That inversion is the parent of D-006 (form-submission data handling) and D-007 (spam protection), which exist only because the site now has a trust boundary.
