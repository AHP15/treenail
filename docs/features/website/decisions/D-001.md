## D-001: Website planning records live at feature scope, not project scope

- **Status**: accepted
- **Date**: 2026-07-05
- **Context**: The Treenail website (marketing landing + detailed documentation) is a new body of work with its own decision tree. The project-level `docs/decisions/` log (D-002…D-027) is entirely about the *product* — skills, build pipeline, distribution, rename — and has its own numbering.
- **Decision**: Record every website decision under the feature scope `docs/features/website/decisions/`, with its own INDEX and independent D-NNN numbering starting at D-001. The project-level `docs/CONVENTIONS-SPEC.md` governs the record format for this scope.
- **Rationale**: Folding website decisions into `docs/decisions/` would clutter the product-architecture log with a distinct concern and conflate two numbering lines. Feature scoping keeps the website's tree self-contained and promotable later via the `promote` skill if any decision turns out to be project-level.
