## D-017: Spam protection is honeypot + Cloudflare Turnstile day-one, with no client-identifier store

- **Status**: accepted
- **Date**: 2026-07-05
- **Supersedes**: D-016
- **Context**: The D-007 → D-016 chain kept trying to make a rate-limiter that is both effective *and* privacy-clean by keying on the client IP. R-010 showed that can't hold: a salted hash of an IP is brute-force-reversible (tiny input space) and pseudonymous data is still personal data under GDPR, so D-016 never actually escaped D-006's "zero PII" posture — it relabelled the same IP-keyed store. R-011 and R-012 showed the store's other costs independently: truncation-for-privacy coarsens the key and throttles shared-egress (NAT/VPN/corporate) users for a stranger's submission, and the KV/Upstash store is an unbudgeted dependency in the form request path with unspecified fail-open/closed and quota behavior. All three failures live in the IP-keyed store itself.
- **Decision**: Remove the IP-keyed rate-limit store entirely. Ship day-one spam protection as **honeypot + Cloudflare Turnstile** — the escalation both D-007 and D-016 held "in reserve" — verified server-side on the form endpoints. Turnstile resists bots without our storing or keying on any client identifier, so D-006's zero-PII posture holds with no reconciliation gymnastics and no own datastore. Provider-side filtering and any native Vercel platform protection remain as backstops. A coarse *global* (non-per-client, no client identifier) endpoint cap to protect metered-provider quota may be added later, gated on observed abuse — but never a per-client PII-keyed store.
- **Rationale**: R-010 collapsed the only reason to prefer an IP limiter over Turnstile — the IP store never stayed inside D-006, so its supposed advantage was illusory, while it carried the over-block (R-011) and dependency (R-012) costs Turnstile does not. Turnstile is privacy-preserving (no cross-site tracking, no PII datastore of ours), invisible for most users, and was already the reserved escalation, so promoting it to day-one is the cheaper and honest path. Cost accepted: a Cloudflare Turnstile account, a client widget script, and one server-side verification call — a Cloudflare dependency and a third-party script, both smaller than the KV store + IP-PII exposure they replace. This narrows R-004 further (the limiter no longer processes IPs at all; only platform logs and analytics do). Note: Turnstile's own residuals — the Cloudflare dependency, the third-party script under D-011/D-012's design bar, edge-case user friction, and whether the deferred global quota cap is actually needed — are unexamined; **red-team-me should be run scoped to D-017 before it ships.**
