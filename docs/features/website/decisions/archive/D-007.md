## D-007: Spam protection is honeypot + server-side rate-limit, with Turnstile held in reserve

- **Status**: superseded
- **Date**: 2026-07-05
- **Date superseded**: 2026-07-05
- **Superseded by**: D-016
- **Context**: The public form endpoints (D-006) POST to metered/list providers, so unprotected spam pollutes the newsletter list and the owner's inbox. Protection ranges from a no-friction honeypot to a full captcha.
- **Decision**: Launch with a honeypot field plus server-side rate-limiting on the form endpoints. Keep Cloudflare Turnstile (privacy-friendly, no reCAPTCHA tracking) ready to add later, gated on observed abuse — not shipped day one.
- **Rationale**: A low-traffic OSS launch rarely draws bot floods, and honeypot + rate-limit adds zero user friction and no third-party script. Turnstile can be dropped in with no data-model change if abuse actually appears, so building it now is speculative. Relying solely on provider-side filtering was rejected because junk would still reach the metered provider/inbox.
