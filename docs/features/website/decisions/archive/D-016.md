## D-016: Spam protection is honeypot + edge rate-limit over ephemeral hashed-IP counters, reconciled with zero-durable-PII

- **Status**: superseded
- **Date**: 2026-07-05
- **Date superseded**: 2026-07-05
- **Superseded by**: D-017
- **Supersedes**: D-007
- **Context**: D-007 specified "honeypot + server-side rate-limit," but R-003 showed the rate-limit half is unimplementable as stated: the form endpoints run as stateless Vercel serverless functions, so in-process counters neither persist across invocations nor share across concurrent instances/regions — the limiter never actually throttles. The obvious fix (a durable IP-keyed store) collides head-on with D-006's "store zero PII itself." D-007's mechanism was under-specified, not wrong in intent; this decision names a working one that stays inside D-006.
- **Decision**: Keep the honeypot as the zero-friction first line. Implement rate-limiting against a **shared ephemeral store** (Vercel KV / Upstash-style) so counters actually persist across serverless instances, but key it on a **salted hash of a truncated client IP with a short TTL (order minutes)** — never the raw IP, never durable retention. The counter store holds only opaque short-lived hashes, not a PII record, so it is consistent with D-006's "no own PII datastore" (that decision governs *durable* submission PII; ephemeral abuse-control hashes are not that). Cloudflare Turnstile remains held in reserve (D-007's stance), gated on observed abuse.
- **Rationale**: This makes the rate-limit real — it survives the stateless-function boundary — while preserving the privacy posture: opaque, salted, truncated, short-TTL keys are not a retained identity store, so D-006 holds without exception. A raw-IP durable store was rejected as reintroducing exactly the PII surface D-006 removed; keeping D-007's in-memory phrasing was rejected as shipping a limiter that does nothing. Cost accepted: one ephemeral-store binding (KV/Upstash) as infra, and the discipline that its keys stay hashed/TTL'd. Note: this narrows but does not eliminate R-004 — platform request logs and analytics still observe raw IPs regardless of the limiter, so the privacy-disclosure accuracy that R-004 covers remains a separate mitigation.
