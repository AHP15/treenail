## D-019: Landing page carries the parity claim as scalable agent chips; per-agent detail moves to the doc

- **Status**: accepted
- **Date**: 2026-07-08
- **Context**: Dropping the ranked tier column (project D-030) leaves the
  question of what replaces the homepage presentation. The homepage
  (`site/app/page.tsx`) currently renders a `TIERS` array as three per-agent
  detail cards with `Best`/`Full` badges (`.tn-tier-badge` /
  `.tn-tier-badge--full` CSS) under the heading "Honest about where it shines."
  The owner intends to add support for more agents over time (cf. project D-031's
  validation gate), which makes per-agent detail cards a scale hazard: three is
  fine, but six or eight becomes a card wall on the landing page and a layout
  redesign each time an agent is added.
- **Decision**: Decouple the two surfaces by what scales on each. The **landing
  page** carries the parity claim in a form that grows gracefully: the one
  parity sentence + the one neutral surface-note sentence (D-021) + a wrapping
  row of **equal-styled agent-name chips** (names only) + a "see what to expect
  on each agent →" link to the doc. Retire the `TIERS` detail cards and the
  `.tn-tier-badge*` CSS. The **`supported-agents` doc** (D-018) holds the full
  per-agent detail, and its table drops the `Tier` column (becoming
  `Agent | What to expect`). The heading moves off "where it shines" to a parity
  frame (e.g. "The full pipeline on every agent").
- **Rationale**: Identical chip styling is itself the equal-support signal, and
  N agents stay one tidy wrapping row instead of N cards — adding an agent
  becomes one chip + one doc table row, never a landing redesign. Keeping the
  detail (rather than collapsing to a single sentence) preserves genuinely
  useful per-agent specifics (e.g. opencode's `--auto` headless note), just
  relocated to the page whose whole job is that detail. Neutralizing the badges
  in place (all identical) was rejected as still badge-shaped hierarchy muscle
  memory.
- **Note (scope)**: This refines, not reverses, project D-030 — the claim and
  the "drop the ranked column" instruction are unchanged; only the homepage
  *form* is chosen here to absorb the growth concern. Per this feature's
  standing tier-accuracy gate (retrospective watch-for #6), any edit to this
  surface must re-pin its copy to the validated parity matrix (project D-029).
