## D-014: Docs are single "latest", unversioned, tracking main

- **Status**: accepted
- **Date**: 2026-07-05
- **Context**: The 2026-07-04 retrospective (Watch-for #2) asks that each cross-cutting policy be interrogated for the case it can't express. Docs versioning is such a policy: snapshot-per-release with a version switcher, or a single unversioned set. The product ships a single semver from 0.1.0 (product D-014).
- **Decision**: Serve one unversioned documentation set that tracks the current release (main). No per-version snapshots, no version switcher, in v1.
- **Rationale**: Versioned docs are a standing maintenance burden and premature before 1.0, when there's one active release and no meaningful population of users pinned to old versions. The boundary case the single-latest rule can't express — a user on an older Treenail reading docs for a newer one — is real but low-impact pre-1.0 and re-openable when a breaking release actually creates version skew.
