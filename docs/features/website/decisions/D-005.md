## D-005: Hybrid docs source-of-truth — derive reference from canonical files, author narrative fresh

- **Status**: accepted
- **Date**: 2026-07-05
- **Context**: Treenail already holds canonical prose in `README.md`, `docs/CONVENTIONS-SPEC.md`, `docs/CONVENTIONS-EXAMPLES.md`, and each skill's `SKILL.md`. Re-typing that into the website creates two sources of the same truth — the exact drift trap the 2026-07-04 retrospective flags (Pattern #3, Watch-for #3: tooling won't catch stale duplicated prose).
- **Decision**: Split docs content by origin. **Derived / single-sourced (never re-typed):** skill-reference pages are generated at build time from each `SKILL.md`'s name + description; record-schema pages import/quote `CONVENTIONS-SPEC.md`. **Hand-authored MDX (unique to the site):** landing copy, the conceptual "planning spine" narrative, the pipeline walkthrough, and a getting-started tutorial. A build-time script performs the `SKILL.md` → reference-page generation.
- **Rationale**: This directly answers the retrospective's top content risk by refusing to duplicate canonical reference prose, while still allowing bespoke narrative that doesn't exist in-repo. Fully hand-authoring everything was rejected as the drift trap; fully generating everything was rejected because marketing/narrative prose can't come from repo files.
- **Note (boundary case, per Watch-for #2)**: The rule the policy can't yet express is build coupling — a repo refactor that moves `README.md`/`docs/**`/`SKILL.md` paths breaks the site build. Accepted deliberately: a loud build failure is strictly better than silent doc drift.
