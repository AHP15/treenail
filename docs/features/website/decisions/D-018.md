## D-018: Rename the agent-support doc to "Supported agents" and drop "tiers" from its URL

- **Status**: accepted
- **Date**: 2026-07-08
- **Context**: Implementing the project-level functional-parity reframe
  (project D-030) on the website (project T-049). The reference doc lives at the
  public URL `/docs/reference/agent-tiers`, titled "Agent support **tiers**," and
  is linked from `site/content/docs/reference/index.mdx` and the docs sidebar.
  "Tiers" is the ranked-hierarchy framing project D-030 rejects, and it sits in
  the URL — the most durable public string on the site. Checked against the tree:
  the site is not published yet (project T-029, "Cut v1: repo public," is still
  `todo`), so there are zero inbound links and a slug change costs nothing now.
  Project retrospective watch-for P6 and this feature's inherited watch-for
  ("price new public strings up front") both apply directly.
- **Decision**: Rename the doc to `/docs/reference/supported-agents`, title
  "Supported agents." Drop the word "tiers" from the URL slug, the page title,
  the sidebar label, and the reference-index link. Do this now, before publish.
- **Rationale**: A URL outlives copy edits, so the hierarchy word must not be
  baked into it. Because nothing is published, renaming is free today and only
  gets more expensive once the site accumulates inbound links. Keeping the old
  slug "for stability" buys almost nothing with zero inbound links while leaving
  "tiers" in the permanent layer; deleting the page loses the useful per-agent
  "what to expect" reference (see D-019, where that detail lands).
- **Note**: Downstream, the project-level CI guard over the support surfaces
  (project T-050, project R-032/R-034) must target the new slug, not
  `agent-tiers`.
