## R-020: The one-sentence surface note assumes a "Claude Code vs the others" binary that breaks the moment a fourth agent renders options

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: accept
- **Date**: 2026-07-08
- **Date resolved**:
- **Description**: D-019 solved the *card* scaling problem (chips grow to N),
  but D-021's single neutral sentence — "questions render as selectable options
  on Claude Code and as prose on the others" — encodes a 1-vs-rest split that
  has its own scaling ceiling the chip decision hid. As soon as a validated new
  agent also renders selectable options (or introduces a third interview
  surface), that sentence becomes factually false, and D-021's "exactly one
  sentence, never stacked" rule leaves no room to express the more complex
  mapping. The parity message's honesty then depends on a caveat whose form was
  fixed to today's agent count, so growth quietly turns an accurate note into an
  inaccurate one on the most credibility-sensitive line on the site.
- **Disposition rationale**: The note is accurate for today's three agents, so
  a same-day supersession of D-021 would speculatively reword copy for an agent
  that does not exist (the over-prediction the retrospective warns against). But
  the boundary case must not be left to re-litigate when it bites (watch-for
  #2), so bind it to a standing mechanism that fires exactly when the triggering
  event — a new agent — occurs.
- **Action**: Add to project D-031's per-agent validation checklist a step that
  re-derives the surface note for the new agent set: confirm the landing/doc
  note still accurately describes the surface split, and — explicitly relaxing
  D-021's "exactly one sentence" literalism, whose *intent* is one note per
  claim, not a permanent sentence count — expand the note beyond one sentence if
  the "Claude Code vs the others" binary no longer holds. Pairs with the
  tier-accuracy gate (watch-for #6). Mitigated by T-026 (adds the revalidation
  step to the checklist; blocked on the project-level per-agent validation
  checklist, project scope, which must exist first — see project D-031). Re-triaged 2026-07-08
  (mitigation-complete: T-026 done): mitigate → accept — the per-agent
  validation checklist now re-derives the surface note when a new agent is
  added, so the note stays accurate as the set grows; it is correct for the
  current three agents and the future-agent case is bound to a standing
  checklist trigger — residual acceptable.
- **Related decisions**: D-021, D-019
