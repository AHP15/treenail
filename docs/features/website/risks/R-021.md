## R-021: D-020's alphabetical order contradicts the non-alphabetical order the same three agents are listed in on README, getting-started, and the CLI doc

- **Severity**: low
- **Likelihood**: high
- **Disposition**: accept
- **Date**: 2026-07-08
- **Date resolved**:
- **Description**: D-020 fixes the chips/table to alphabetical order (Claude
  Code, Codex CLI, opencode), but the identical three-agent list already appears
  in a *different*, non-alphabetical order — "Claude Code, opencode, Codex CLI"
  — in `README.md`, `getting-started/index.mdx`, and `reference/cli.mdx`. So a
  visitor moving between the landing chips and the docs sees two different agent
  orders, which undercuts the very neutrality rationale D-020 rested on, and any
  CI guard (project T-050) that asserts a canonical order has an ambiguous target
  across surfaces. D-020 scoped itself to the chips/table and never confronted
  the other surfaces carrying the same list. (A related latent case: with only
  three agents alphabetical is indistinguishable from Claude-Code-primacy, so a
  future agent sorting before "Claude" will silently demote Claude Code — an
  intended-but-unconfronted consequence of the rule.)
- **Disposition rationale**: Low severity, but not mere ceremony — a canonical
  order is a *prerequisite* for the planned support-surface CI guard (project
  T-050) to have an unambiguous target, so resolving the inconsistency unblocks
  that guard rather than adding scope to it.
- **Action**: Adopt one canonical agent order (D-020's alphabetical: Claude
  Code, Codex CLI, opencode) and apply it uniformly to the landing chips, the
  doc table, `README.md`, `getting-started/index.mdx`, and `reference/cli.mdx`;
  have the project-level support-surface CI guard (project scope, from
  R-032/R-034) assert that order across all list surfaces. Mitigated by T-025
  (aligns README, getting-started, and cli.mdx to the canonical order; the new
  chips/table in T-023/T-024 are already-ordered content). Re-triaged
  2026-07-08 (mitigation-complete: T-025 done): mitigate → accept — one
  canonical agent order is now applied uniformly across all list surfaces and
  asserted by the project support-surface CI guard; low-severity residual
  acceptable.
