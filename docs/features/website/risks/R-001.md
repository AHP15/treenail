## R-001: Site tooling and build artifacts leak into the published npm product tarball

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-05
- **Date resolved**:
- **Description**: D-004 puts the site in a `site/` subdirectory of the product repo, which also ships a committed `dist/` and publishes to npm. Unless the package `files` allowlist / `.npmignore` and the packed-tarball smoke explicitly exclude `site/`, the site's source, `node_modules`, `.next` build output, and Fumadocs assets get swept into `npm publish`, bloating the product package by megabytes and shipping marketing/website code to every `npx treenail install` user. The decision names this cost ("`.gitignore`/CI must keep the site's Node tooling from polluting the product package") but names no mechanism or gate that enforces it.
- **Disposition rationale**: The decision stands; the gap is a missing enforcement mechanism, not a wrong choice. A cheap deterministic guard closes it, and the project already runs a packed-tarball smoke (product T-034) that is the natural place to assert the exclusion.
- **Action**: Mitigate by (1) constraining the published package via an explicit `files` allowlist (or `.npmignore` entry) that excludes `site/`, and (2) extending the packed-tarball smoke to assert no `site/**` path appears in `npm pack` output and that the tarball size stays under a fixed ceiling. Fails loud at publish time rather than shipping bloat. Tracked by T-016.
- **Related decisions**: D-004
