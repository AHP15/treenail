## R-002: Single-sourcing fails silently on intra-file structure drift, not just loudly on path moves

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-05
- **Date resolved**:
- **Description**: D-005's safety claim is that single-sourcing degrades to "a loud build failure" rather than silent drift — but that only holds for the failure mode it considered: a file *path* moving. The build reads *inside* those files: skill `name`+`description` fields, and quoted/extracted sections of `CONVENTIONS-SPEC.md` (record-schema pages). Renaming a spec heading, restructuring a section, reflowing a `SKILL.md` description, or adding/removing a skill leaves every path intact, so the build still succeeds — it just emits a truncated, empty, or stale reference page. This is exactly the silent duplicated-prose drift the retrospective (Pattern #3 / Watch-for #3) says tooling won't catch, reintroduced one layer down from where D-005 defended against it.
- **Disposition rationale**: D-005's derive-don't-duplicate choice is right; the residual is that its "loud failure" guarantee only covers path moves. The fix is to extend the loudness to intra-file drift with build-time assertions, not to change the sourcing strategy.
- **Action**: Mitigate by making the generation step assert its extraction succeeded rather than degrade silently: each derived page must resolve a non-empty `name`+`description` (fail the build on empty), each quoted spec section must be located by a stable anchor and error if the anchor is absent, and the derived skill-reference set must be enumerated from the skills directory (not a hardcoded count) with a build-time check that every enumerated skill produced a page and vice-versa. Any missing/empty extraction fails the build loudly. Tracked by T-004.
- **Related decisions**: D-005, D-010
