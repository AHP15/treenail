## R-012: The KV/Upstash store D-016 adds becomes an unbudgeted dependency in the request path, with fail-open/closed and quota behavior unspecified

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: fix
- **Date**: 2026-07-05
- **Date resolved**: 2026-07-05
- **Description**: D-016 introduces a shared ephemeral store (Vercel KV / Upstash) that D-002/D-006 had deliberately avoided, and puts it in the live path of form handling — but it does not say what happens when that store is unavailable, slow, or over quota. Unspecified, the limiter either fails open (submissions flow with no protection, silently negating D-016) or fails closed (every submission is blocked while the store is down) — and D-016 picks neither. Cost/quota compounds it: the title says "edge rate-limit," and if implemented as edge middleware the counter is touched on *every* request, not just form POSTs, so a docs-heavy site (D-010 is reference-complete) or a launch spike burns the free-tier request quota on page views alone, at which point the store starts erroring and the fail-mode question above decides whether the site's forms break or go unprotected.
- **Disposition rationale**: The dependency and its unspecified fail-mode exist only because of the KV/Upstash store; D-017 removes that store from the request path, so there is nothing left to fail open/closed or to burn quota. Retired by the same supersession, not an independent guard.
- **Action**: Superseded by D-017, which removes the KV/Upstash store entirely (honeypot + Turnstile, no shared counter in the form path). Any later global quota cap is explicitly gated on observed abuse, not a launch dependency. Removes the failure mode.
- **Related decisions**: D-016, D-002
