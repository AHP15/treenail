## R-004: The published "zero PII / no consent banner required" claim is contradicted by IP capture in the limiter, platform logs, and analytics

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-05
- **Date resolved**:
- **Description**: D-006 reduces the privacy commitment to "a short disclosure note" asserting the site stores zero PII, and D-015 asserts cookieless Vercel Analytics needs "no consent banner." But a working rate-limiter (now D-016) keys on a hashed IP, Vercel's request/function logs record raw client IPs, and IP is personal data under GDPR/ePrivacy — so the site does process PII, and the "no consent required" conclusion is a legal assumption, not a settled fact, particularly for EU visitors. A privacy disclosure that materially understates what is collected is worse than none: it converts an honest gap into a false public statement on the exact trust boundary D-002 introduced.
- **Disposition rationale**: The zero-durable-PII posture (D-006) is intact and worth keeping; what's wrong is the *claim's accuracy*, which is a copy-and-verification problem, not a design change. D-016 narrows the limiter's exposure (hashed/TTL'd) but platform logs and analytics still observe raw IPs, so the disclosure must be corrected regardless.
- **Action**: Mitigate by (1) writing the disclosure note to state truthfully that transient IP processing occurs in platform request/function logs, the abuse-control limiter (hashed, per D-016), and cookieless analytics — while no submission PII is stored in an own datastore; and (2) verifying the "no consent banner required" conclusion against Vercel Analytics' actual cookieless data handling and EU ePrivacy/GDPR guidance before launch, adding a banner/notice if that check fails. Gate the copy on that verification as a launch checklist item. Tracked by T-015.
- **Related decisions**: D-006, D-007, D-015
