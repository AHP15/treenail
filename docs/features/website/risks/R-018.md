## R-018: The slug rename is a multi-file atomic edit, and fumadocs' `meta.json` pins nav by slug — a missed reference silently drops the page or 404s the link

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-08
- **Date resolved**:
- **Description**: D-018 justifies the rename on "zero inbound links because
  unpublished," but that is only true for *external* links — the old slug
  `agent-tiers` is referenced internally in at least two coupled files:
  `site/content/docs/reference/meta.json` (the explicit fumadocs page-order
  array `["index","cli","agent-tiers","graphiti"]`) and the reference-index
  link in `index.mdx`. Renaming the `.mdx` file without updating every one of
  these leaves the page dropped from the sidebar (meta.json still names the old
  slug) or a dead in-site link, and fumadocs fails these quietly at build/nav
  rather than loudly. The decision text enumerated "sidebar label" and
  "reference-index link" but not `meta.json` specifically, which is the exact
  reference most likely to be missed.
- **Disposition rationale**: D-018 itself is sound; the failure is
  implementation completeness, not a decision flaw, so keep the decision and add
  a guard that the rename touches every coupled reference.
- **Action**: Add a guard to the rename work: update the `.mdx` file, the
  `meta.json` page-order array, and the reference-index link together, then
  verify no `agent-tiers` string survives in `site/` and the built sidebar/link
  resolves to the new slug. Fold the surviving-old-slug check into the
  project-level support-surface CI guard (project scope, from R-032/R-034) so a
  future reintroduction is caught. Mitigated by T-023 (rename + completeness
  sweep: no surviving `agent-tiers`, nav resolves).
- **Related decisions**: D-018
