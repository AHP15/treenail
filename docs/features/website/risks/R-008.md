## R-008: Preview deployments run live form endpoints against real providers with real secrets

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-05
- **Date resolved**:
- **Description**: D-002 gives the site server endpoints that POST to metered/list providers using secret API keys held as Vercel env vars, and D-004 wires the site into a repo where every branch/PR gets a Vercel preview deploy. If preview environments inherit the production provider secrets (Vercel's default for same-repo branches), then every preview — and any test submission against one — sends real transactional email to the owner's inbox and writes real entries into the production newsletter list, polluting exactly the metered provider and inbox D-007/D-016 tried to protect. Contributor forks add a secret-exposure dimension if env scoping is not deliberately restricted to production.
- **Disposition rationale**: The Vercel runtime + monorepo choices (D-002/D-004) are sound; the exposure is an environment-scoping default, closable by configuration and a fail-safe in the endpoint, so mitigate.
- **Action**: Mitigate by (1) scoping the provider secrets to the Production environment only in Vercel, so Preview/Development do not receive them; (2) making the form endpoints fail safe — when provider keys are absent (preview/dev) they short-circuit to a no-op/sandbox response instead of erroring or falling through to a real send; and (3) confirming forked-PR previews never receive secrets. Verify by submitting against a preview deploy and asserting no real email/list write occurs. Tracked by T-014.
- **Related decisions**: D-002, D-004, D-006
