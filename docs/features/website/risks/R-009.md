## R-009: Docs track main while npm ships the last release, so the site documents behavior users can't yet install

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-05
- **Date resolved**:
- **Description**: D-014 serves a single unversioned docs set that tracks main, but users install the last *published* npm/plugin release via `npx treenail install`. Whenever main is ahead of the last publish — the normal state between releases — the site's install steps, CLI reference, and skill/record descriptions (many derived from main's files per D-005) describe behavior, flags, or skills that the installed package does not yet have. This is a distinct failure from the boundary D-014 already named (an old user reading newer docs): here the *current* site actively documents unreleased behavior to *every* visitor, and a first-run user following the quickstart hits commands or output that don't match. The mismatch is silent because nothing pins the docs build to the released version.
- **Disposition rationale**: The unversioned single-latest choice (D-014) is right pre-1.0 and shouldn't be reversed, but the sharp edge — first-run quickstart/CLI steps describing unreleased behavior — is closable without introducing versioned docs. So mitigate narrowly rather than accept the first-run break.
- **Action**: Mitigate by (1) pinning the *install-critical* derived surfaces — the quickstart `npx` commands, install steps, and CLI reference — to the last published release (read the published version, not raw main, for those pages) while narrative/conceptual pages continue to track main per D-014; and (2) showing a small "docs track the latest release (vX.Y.Z); newest changes may be ahead" note so the main-ahead state is disclosed rather than silent. Leaves D-014 intact. Tracked by T-017.
- **Related decisions**: D-014, D-005
