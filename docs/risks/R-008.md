## R-008: Multi-channel installs create version skew between skill text and the ~/.keel runtime

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-02
- **Date resolved**:
- **Description**: D-014's lockstep versioning assumes one install path, but D-007 ships three: marketplace plugins update on Claude's cadence while ~/.keel updates via the CLI. A user with both channels can hold v0.3 skill text calling a script flag that the v0.2 scripts in ~/.keel don't have (or vice versa), producing failures that neither version alone would show and that are hard to reproduce from a bug report.
- **Disposition rationale**: Medium/medium but the failure mode is hard-to-reproduce bug reports; a version handshake converts silent skew into a one-line actionable error at trivial cost, keeping D-014's lockstep model intact.
- **Action**: The build stamps each provider's skill output with the semver it was built from; shared scripts compare that stamp against ~/.keel/VERSION at invocation and fail fast with 'skill text vX / runtime vY — run npx keel-skills update' on mismatch. Mitigated by T-017 (build/install version stamps) and T-018 (runtime handshake).
- **Related decisions**: D-007, D-014
