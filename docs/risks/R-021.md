## R-021: The rename races in-flight v1 distribution work — any artifact shipped under Keel branding first multiplies cutover cost

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-04
- **Date resolved**:
- **Description**: v1 tasks are mid-flight (T-025—T-034 touch the plugin, installer packaging, and release gate) and `.claude-plugin/marketplace.json` plus the `keel-skills@0.0.1` placeholder already exist publicly under the old identity. A marketplace plugin rename is a delist-and-relist — existing installs of plugin `keel` would silently stop receiving updates — and every keel-branded artifact that ships before the sweep lands (a marketplace listing, a tagged release, a published dist) converts the rename from a repo-local edit into a public migration with orphaned `~/.keel` state on user machines. D-023 sequences npm reservation but nothing sequences the rename against the v1 pipeline itself.
- **Disposition rationale**: The failure is purely an ordering problem — every artifact is still private or placeholder-grade today — so a sequencing constraint eliminates it outright while the window is open; medium × medium becomes near-zero if the rename phase is a hard predecessor of all publish tasks.
- **Action**: T-037 — the v1 release gate asserts no keel-branded artifact is published: plugin manifest name, marketplace entry, and npm tarball must all read `treenail` before anything ships. Plus a sequencing constraint for `sequence-work`: the rename phase (T-035 reservation, T-036 sweep) is a blocking predecessor of every outward-publishing task — marketplace listing, npm v1 publish (T-029), tagged release.
- **Related decisions**: D-021, D-023, D-007, D-015
