## R-037: Scoping the rationale rule to challenge-me leaves the same defect legal in other choice-surfacing skills, and its revisit trigger may never fire

- **Severity**: low
- **Likelihood**: low
- **Disposition**: accept
- **Date**: 2026-07-08
- **Date resolved**:
- **Description**: D-032 hardens only `challenge-me` and defers a shared interview-protocol snippet until "a second interview-bearing skill appears." But other shipped skills already surface user-facing choices where a visible "why" matters — `triage-risks` has the user confirm dispositions, `promote` asks which records to promote, `reconcile-status` recommends routing. The survey that justified single-skill scope counted only the strict recommendation-first *loop*, not every place a choice is presented, so the same "surface a choice without a visible rationale" failure stays legal everywhere else. And because those consumers already exist, the "revisit when a second interview skill appears" trigger is unlikely to ever fire — the second consumer is already here, unrecognized, so the deferral becomes permanent by construction.
- **Disposition rationale**: Low/low — the recommendation-first interview loop is genuinely challenge-me's; triage-risks/promote present lower-stakes confirmations where a missing rationale is minor. Single-skill scope is the right size now.
- **Action**: none — accept single-skill scope. Reframe D-032's revisit trigger so it can actually fire: extract a shared interview-protocol snippet when the missing-rationale defect is *observed to recur in another skill*, not on the abstract appearance of "a second interview skill." That observable event neutralizes the "trigger never fires" concern.
- **Related decisions**: D-032
