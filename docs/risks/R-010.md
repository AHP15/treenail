## R-010: Windows is claimed officially supported without Windows CI or a path-portability audit

- **Severity**: high
- **Likelihood**: high
- **Disposition**: mitigate
- **Date**: 2026-07-02
- **Date resolved**:
- **Description**: D-009 promises native-Windows support, but the _shared scripts were written and tested only on macOS — POSIX path assumptions (~ expansion, forward slashes, case sensitivity), Git Bash vs cmd differences, and CRLF handling are all unaudited, and D-012's CI has no Windows runner. The likely outcome is INDEX/record corruption or hard failures for Windows users of an officially supported platform, which is worse than the WSL-best-effort posture it replaced.
- **Disposition rationale**: High severity and high likelihood: an official support claim (D-009) backed by zero Windows testing is a promise the codebase hasn't earned. The guard is exactly the work D-009's rationale already implies — make it explicit and gate v1 on it.
- **Action**: Add a Windows runner to CI running the _shared script tests plus an installer smoke test; audit scripts for POSIX assumptions (~ expansion, path separators, CRLF, case sensitivity) as part of the mint-id.sh Python port; make the Windows CI job green a v1 ship criterion (D-015). Mitigated by T-005 (mint-id Python port), T-006 (POSIX-assumption audit), and T-024 (Windows CI runner).
- **Related decisions**: D-009, D-012, D-015
