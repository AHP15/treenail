## R-034: The support bar is an unenforced documentary norm — nothing stops an agent being advertised before it is validated

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-08
- **Date resolved**:
- **Description**: D-031 says a new agent is advertised as supported only after passing parity validation, but it specifies no gate, no owner, and no record the validation happened. A maintainer eager to announce "now on Cursor" can add the name to the README supported list and the site in one commit with nothing — no CI check, no required artifact, no reviewer prompt — blocking it. This reproduces the exact notional-vs-exercised gap the 2026-07-04 watch-for P4 flags (a policy asserted, not exercised), one level up from the skills: the equal-support claim decays agent-by-agent as the roster grows optimistically, and the decay is invisible because the bar lives only in prose.
- **Disposition rationale**: Medium/medium — D-031's whole purpose is keeping the equal-support claim honest, which an unenforced prose norm quietly defeats. A lightweight artifact-of-record guard adds teeth without heavyweight CI. Keep D-031; give it an enforcement surface.
- **Action**: Keep D-031. Guard: require a dated, committed per-agent parity-validation record (reusing the D-029 doc as a template) as the artifact of record for each supported agent; the README/site supported-list entry links its record. Adding an agent without a linked validation record is then visibly incomplete and catchable in review (optionally a repo check that every advertised agent name resolves to a validation doc). Mitigated by T-051 (document the bar + require records) and T-050 (the mechanical agent→record check).
- **Related decisions**: D-031
