## R-042: Project-level manifest ownership mistakes can overwrite or prune user repository files

- **Severity**: high
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-10
- **Date resolved**:
- **Description**: D-035 lets experimental adapters write project-level config behind a Treenail-managed manifest, then prune removed managed files on update. If the manifest is stale across branches, copied between projects, corrupted, or too broad about ownership, update can back up, overwrite, or delete files inside the user's repo that Treenail no longer has a valid claim to control.
- **Disposition rationale**: High severity with medium likelihood makes this
  the sharpest project-level install risk, but D-035 already chose the right
  ownership direction. The mitigation should harden what counts as a
  Treenail-owned file before overwrite or prune is legal.
- **Action**: Keep D-035. Guard: define manifest ownership narrowly enough that
  update can only overwrite or prune files whose path, prior content hash or
  Treenail marker, source adapter, and install root all match the manifest's
  claim. If any ownership check fails, interactive update asks before backing
  up or replacing the file and non-interactive update refuses unless explicitly
  forced. Mitigated by T-059 and T-060.
- **Related decisions**: D-035
