## R-020: The rename is a 73-file mass edit with hard-cutover semantics and no regression harness — one missed reference fails at runtime with no fallback

- **Severity**: high
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-04
- **Date resolved**:
- **Description**: `KEEL_HOME`, `~/.keel`, `keel-skills`, and `bootstrap_keel_home.py` are load-bearing in 73 files across `skills/`, `cli/`, `build.py`, and committed `dist/` — including inside skill prose that agents execute verbatim. D-023 forbids any compat shim, so a single surviving `KEEL_HOME` read or `~/.keel` path after cutover resolves to a directory that no longer exists and fails mid-skill-run, not at install time. This is the R-006 mass-edit pattern again (accepted there *without* cutover semantics), compounded by R-005's still-open lack of end-to-end validation: nothing currently proves a renamed install actually runs the pipeline.
- **Disposition rationale**: High severity × medium likelihood with hard-cutover semantics means "hope the grep was thorough" is not a plan; but the failure mode is fully machine-detectable (a token grep) and machine-exercisable (an install-and-run smoke), so guards close it cheaply. R-006's accept doesn't transfer: that edit had the repo as its own oracle, this one has a runtime dependency chain.
- **Action**: Three guards: (1) T-036 — the sweep renames `dist/` only by regenerating through `build.py`, never by hand-editing generated files; (2) T-037 — a release-gate grep asserting zero live `keel|KEEL_HOME|keel-skills` tokens outside `docs/` historical records and lineage lore after cutover; (3) T-038 — an end-to-end smoke on a clean machine/tmp-HOME, `npx treenail install` then one full skill run against `~/.treenail`, folded into R-005's release-gate validation so the renamed runtime is what v1 actually certifies.
- **Related decisions**: D-021, D-022, D-023
