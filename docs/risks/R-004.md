## R-004: The pipeline's interactive core degrades badly on opencode/Codex and the product is judged by its weakest port

- **Severity**: high
- **Likelihood**: high
- **Disposition**: mitigate
- **Date**: 2026-07-02
- **Date resolved**:
- **Description**: Keel's flagship skills (challenge-me, red-team-me, task-brief) are built around structured multi-option interviews, skill-invoking-skill chaining, and long agentic sessions — capabilities Claude Code has and opencode/Codex only partially match. The build step (D-004) can translate file formats but cannot conjure missing agent capabilities, so 2 of 3 advertised v1 targets may deliver a visibly worse pipeline; public reviews and GitHub issues will judge Keel by that degraded experience.
- **Disposition rationale**: High severity and high likelihood on a launch-defining surface: the product will be judged publicly by its weakest port. Dropping targets would gut D-015's cut, but expectation-setting plus pre-launch validation on each agent bounds the damage without changing decisions.
- **Action**: Before v1: run the flagship interactive skills (challenge-me, red-team-me, task-brief) end-to-end on opencode and Codex and record what degrades; publish an honest per-agent support-tier matrix in the README ('best on Claude Code'); have the build inject per-provider notes (per D-005) adapting interview phrasing to each agent's capabilities. Overlaps with R-005's validation pass. Mitigated by T-025 (opencode/Codex degradation spike), T-026 (per-provider notes injection), and T-027 (README support-tier matrix).
