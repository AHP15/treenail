## R-026: Silent Graphiti degradation makes a broken optional setup undiagnosable — the user cannot tell "no prior art" from "my backend is down"

- **Severity**: low
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-04
- **Date resolved**:
- **Description**: D-013 relies on `graph_query.py` degrading silently when Graphiti is unconfigured — and it does: `main()` catches `GraphUnavailable` and every other exception and returns 0 with no output. But that same blanket silence also covers the *misconfigured* case. A user who followed the optional-setup README (installed `graphiti-core`, set `NEO4J_URI`/creds or `FALKORDB_URI`) but whose backend is unreachable, whose credentials rotated, or whose `graphiti-core` version mismatched gets exactly the same zero output as someone who never set it up. The script prints "(no related prior records found)" only on a *successful* empty search; a broken backend prints nothing at all. Because setup is the user's job with no installer check (D-013) and no health command, a user who invested in Graphiti cannot distinguish "working, nothing related" from "silently broken," and gets no error to act on — the optional cross-scope recall can be dead for an entire project with no one noticing. The graceful-degradation property that makes absence safe makes misconfiguration invisible.
- **Disposition rationale**: Low severity — only users who opted into Graphiti and whose backend later broke — but the guard is cheap and targeted: it removes a silent-failure trap without touching D-013's graceful-degradation-when-absent property.
- **Action**: Keep D-013; add a diagnostic path so a configured-but-unreachable Graphiti is not indistinguishable from unconfigured. When a Graphiti backend IS selected via env (NEO4J_* or FALKORDB_URI set) but the client cannot connect or search, emit a one-line advisory to stderr — e.g. 'Graphiti configured but unreachable: <reason>; proceeding without prior-art' — while keeping the fully-silent skip when no Graphiti env is set at all. Optionally expose it as a graph-sync/query health check the README's optional-setup section points at.
- **Related decisions**: D-013
