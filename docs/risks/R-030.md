## R-030: Removing the only conforming authoring scaffold risks the next interview-family skill being authored with malformed frontmatter or a missed build-injection assumption

- **Severity**: low
- **Likelihood**: low
- **Disposition**: accept
- **Date**: 2026-07-04
- **Date resolved**:
- **Description**: The `skills/_templates/` scaffolds were the sole worked
  reference for authoring a new agent-neutral interview skill (D-005) — the
  exact frontmatter shape and the seams where `build.py` injects the
  TREENAIL_HOME note, the per-provider preamble, and the skill-version stamp.
  With them deleted (D-026), a future author of a new skill (e.g. a
  `threat-model-me`) must reverse-engineer those conventions from an existing
  `SKILL.md` plus `build.py`, and a missed assumption surfaces only when the
  build or a specific provider adapter chokes — the late-boundary-exposure
  shape of retro 2026-07-04 Pattern #2. Git history holds the scaffolds, but
  only for an author who knows they once existed and goes looking.
- **Disposition rationale**: Low/low — no new interview-family skill is planned,
  the authoring conventions remain documented in `CONVENTIONS-SPEC.md` and
  readable in `build.py`'s injection seams, and a non-conformant new skill fails
  loudly at build/adapter time rather than shipping silently. The scaffolds are
  recoverable from git, so the residual is a single future authoring task's
  friction, not lost capability.
- **Action**: none (accept). Recovery path if a new interview-family skill is
  ever authored: restore the scaffolds from git commit 56f8807
  (`git show 56f8807:skills/_templates/challenge-me/SKILL.template.md`), or
  derive from an existing `SKILL.md` plus `build.py`'s TREENAIL_HOME-note,
  per-provider-preamble, and skill-version-stamp injection seams.
- **Related decisions**: D-026
