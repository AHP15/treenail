## R-007: Plugin-marketplace installs bypass the installer, so ~/.keel is never provisioned

- **Severity**: high
- **Likelihood**: high
- **Disposition**: mitigate
- **Date**: 2026-07-02
- **Date resolved**:
- **Description**: D-006 makes skills depend on scripts/templates in ~/.keel, which only the npx installer creates. D-007's Claude plugin-marketplace channel installs skill text through Claude's plugin system without ever running that installer. A plugin-only user invokes challenge-me, the skill calls ~/.keel/scripts/mint-id..., nothing is there, and the flagship skill fails on first use through the channel with the least-technical audience.
- **Disposition rationale**: High severity and high likelihood, landing on the flagship skill for the least-technical channel — but no decision is wrong; D-007 added a channel without a provisioning story, and the build step (D-004) is the natural place for the guard.
- **Action**: The plugin-channel build bundles the shared runtime inside the plugin and rewrites script/template references to plugin-relative paths (or bootstraps ~/.keel from bundled assets on first run); as a backstop, every scripted-invocation failure states plainly: 'Keel runtime missing — run npx keel-skills install'. Mitigated by T-019 (plugin bundles the runtime) and T-020 (runtime-missing failure message).
- **Related decisions**: D-006, D-007
