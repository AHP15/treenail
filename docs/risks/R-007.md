## R-007: Plugin-marketplace installs bypass the installer, so ~/.keel is never provisioned

- **Severity**: high
- **Likelihood**: high
- **Disposition**: accept
- **Date**: 2026-07-04
- **Date resolved**:
- **Description**: D-006 makes skills depend on scripts/templates in ~/.keel, which only the npx installer creates. D-007's Claude plugin-marketplace channel installs skill text through Claude's plugin system without ever running that installer. A plugin-only user invokes challenge-me, the skill calls ~/.keel/scripts/mint-id..., nothing is there, and the flagship skill fails on first use through the channel with the least-technical audience.
- **Disposition rationale**: Residual acceptable: the plugin build bundles the runtime and provisions ~/.treenail on first session, and every scripted-invocation failure states the runtime-missing backstop message — a plugin-only user no longer hits an unprovisioned runtime.
- **Action**: Accept — provisioning gap closed; mitigated by T-019 (plugin bundles the runtime + SessionStart bootstrap) and T-020 (runtime-missing failure message), both shipped.
- **Related decisions**: D-006, D-007
