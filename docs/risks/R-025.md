## R-025: User-level-only installs give a team no shared version pin, so teammates on different Treenail versions write divergent records into one committed docs/

- **Severity**: medium
- **Likelihood**: low
- **Disposition**: defer
- **Date**: 2026-07-04
- **Date resolved**:
- **Description**: D-008 defers project-level/team installs, so each teammate installs Treenail at user level independently, with no project-pinned tool version. The per-project spec-version marker (T-022) freezes the record *schema* but not the tool's skill prose or `_shared` script logic, which evolve across releases. Two teammates on different Treenail versions running the pipeline against the same committed `docs/` can therefore produce structurally divergent decision/risk bodies and INDEX projections — an inconsistent planning history with no shared version anchor to coordinate on, and no signal that they have drifted. The decision's own rationale names "team version skew" as a deferred concern; deferring it leaves teams — a natural early audience for a planning tool kept in a shared repo — with the failure and no v1 mitigation. Distinct from R-008 (multi-*channel* skew for a single user): this is cross-*user* skew created by the user-level-only install model.
- **Disposition rationale**: Medium severity but low likelihood inside v1: D-008/D-015 deliberately defer project-level/team installs, and the divergence only bites once a team adopts AND multiple tool versions run against one committed docs/. A natural revisit point exists — the deferred project-level-install design pass — so this is a watch-for with a real trigger, not action now.
- **Action**: Defer trigger: revisit when the project-level/team install design pass begins (the deferred half of D-008/D-015), or immediately on the first user report of cross-teammate record divergence in a shared docs/ — whichever comes first. At that point decide the shared-version-pin mechanism (e.g. a project-pinned tool version alongside the T-022 spec marker).
- **Related decisions**: D-008
