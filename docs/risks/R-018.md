## R-018: The `treenail` npm name is sniped before the placeholder publish, voiding the rename's premise

- **Severity**: medium
- **Likelihood**: low
- **Disposition**: mitigate
- **Date**: 2026-07-04
- **Date resolved**:
- **Description**: D-021 chose Treenail *because* the namespace is clean, and D-023 acknowledges that cleanliness is perishable — but the reservation is a manual step gated on the owner's npm credentials, with no deadline or owning task yet. If anyone publishes `treenail` first (name-squatters watch fresh GitHub repos and renamed projects), the one hard gate the rename was built on fails after the brand decision is already recorded and the sweep possibly underway. Unlike R-009 (keel-skills), a lost name here can't be dodged with a compound: D-022 makes the bare name load-bearing on every surface.
- **Disposition rationale**: The guard is nearly free and the exposure window is entirely self-inflicted schedule slack; severity is medium only because the failure invalidates D-021's premise rather than any shipped artifact.
- **Action**: T-035 — the `treenail@0.0.1` placeholder publish, first task of the rename phase, sequenced before any rename edit lands in the repo; it re-verifies `npm view treenail` is still 404 immediately before publishing and escalates to a name re-decision if not.
- **Related decisions**: D-021, D-022, D-023
