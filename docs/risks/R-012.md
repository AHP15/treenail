## R-012: Frozen per-project conventions require scripts to stay backward-compatible forever, with no version marker to dispatch on

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-02
- **Date resolved**:
- **Description**: D-010 freezes each project's copied conventions at adoption time while ~/.keel scripts and skills upgrade globally. Nothing in a project's docs/ records which spec version it was created under, so a future reindex.py or audit.py that changes record parsing cannot detect old-format projects — it will either corrupt their INDEX files or refuse to run, and the failure lands in the user's own planning records, the highest-trust data Keel touches.
- **Disposition rationale**: The corruption lands in users' highest-trust data, and the marker must exist *before* the first format change to be of any use — it cannot be retrofitted onto already-adopted projects. Cheap to add now.
- **Action**: Stamp a spec-version marker into each project's copied conventions at adoption time (e.g. a version line in the copied CONVENTIONS-SPEC.md or a docs/.keel-version file); future script versions check it and refuse loudly (never guess) on records from an unknown spec version. Mitigated by T-022 (spec-version marker + loud refusal).
- **Related decisions**: D-010
