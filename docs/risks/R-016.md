## R-016: On Node 18/20 the installer half-works, then crashes cryptically instead of stating the version requirement

- **Severity**: medium
- **Likelihood**: medium
- **Disposition**: fix
- **Date**: 2026-07-03
- **Date resolved**: 2026-07-03
- **Description**: D-017 sets `engines: ">=22"` and calls it advisory, assuming pre-22 Node fails with a "legible syntax/loader error" — but it doesn't. ESM parses fine on Node 18, so `help` and `detect` succeed; only `install` touches `import.meta.dirname`, which is `undefined` below 20.11, so `path.join(undefined, ...)` throws `TypeError [ERR_INVALID_ARG_TYPE]` deep in `distRoot()`. npx merely prints an EBADENGINE warning and runs anyway, and 18/20 remain common as distro/corporate system Node. First-touch experience for those users: the tool visibly works, then crashes with a stack trace that never mentions Node versions.
- **Disposition rationale**: Medium×medium on the product's first touch, and the failure mode contradicts the superseded decision's own stated premise; the fix is a ~3-line gate, far cheaper than the reputation cost of a cryptic first-run crash.
- **Action**: Superseded D-017 with D-020 — a startup Node-version gate in `main()` replaces the failure mode (clear "requires Node 22+" message instead of a deep TypeError). Resolved 2026-07-03: the gate shipped via T-031 (done), verified to exit 1 with the version message on simulated Node 18 before any subcommand logic runs.
- **Related decisions**: D-017, D-016, D-020
