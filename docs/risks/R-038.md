## R-038: Thin adapters cannot express runtime-specific skill semantics, so candidates install cleanly but fail real workflows

- **Severity**: high
- **Likelihood**: medium
- **Disposition**: mitigate
- **Date**: 2026-07-10
- **Date resolved**:
- **Description**: D-033 assumes the Claude-style `SKILL.md` source can remain canonical while each new runtime is reached through a thin adapter. If Pi, Cursor, Kimi Code, or Kiro require structured metadata, placement rules, permission declarations, or interaction affordances that do not map cleanly from the canonical file, Treenail can produce an adapter that packages and installs while silently failing the behaviors the skill depends on.
- **Disposition rationale**: High severity with medium likelihood makes this a
  build-time guard, not a reason to replace D-033. The canonical source can
  remain Claude-style if every candidate adapter has to prove its runtime
  mapping preserves the skill behaviors Treenail relies on.
- **Action**: Keep D-033. Guard: for each candidate adapter, require an explicit
  runtime-mapping checklist before implementation is considered complete. The
  checklist records how the adapter handles frontmatter/metadata, placement,
  project vs user config, tool or permission instructions, user-interview
  affordances, and any source content that is dropped or transformed; a
  candidate with lossy or unknown mappings remains experimental until the loss
  is either resolved or called out in its validation record. Mitigated by
  T-056, T-061, T-062, T-063, and T-064.
- **Related decisions**: D-033
