## D-035: Experimental project-level adapter config uses a managed-install substrate with pruning

- **Status**: accepted
- **Date**: 2026-07-10
- **Context**: Some candidate runtimes may only support durable instructions via
  project-level agent configuration, while D-008 keeps normal supported-agent
  installs user-level. The owner also wants Treenail to support project-level
  skills in the future, and the latest retrospective surfaced stale installed
  files as an update risk that should be decided before more adapter surfaces
  land.
- **Decision**: Experimental adapters may write project-level agent config only
  when the target runtime requires it, and only behind explicit
  `--experimental` opt-in. This introduces a limited experimental
  project-level managed-install substrate: write only Treenail-owned files,
  record them in a manifest, refuse or back up local edits before overwriting,
  and make the behavior reusable for future project-level skills. Normal
  supported-agent installs remain user-level unless a later decision graduates
  project-level installs generally. Experimental user-level and project-level
  managed installs prune removed Treenail-managed files on update after
  manifest verification; locally edited files are backed up with confirmation,
  while non-interactive updates refuse unless forced.
- **Rationale**: Treating project-level config as a small substrate avoids
  creating one-off adapter exceptions that later project-level skills would have
  to unwind. Manifested writes preserve D-010's "do not touch user data blindly"
  spirit while letting runtimes with project-only instruction surfaces be
  tested. Pruning prevents obsolete candidate files from continuing to steer an
  agent after the adapter changes shape, without deleting files Treenail cannot
  prove it owns.
