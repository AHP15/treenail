## D-034: Experimental adapters are bundled and opt-in, with dossier plus packaged validation before graduation

- **Status**: accepted
- **Date**: 2026-07-10
- **Context**: Candidate adapters need the real installer channel to be
  validated honestly, but installing them by default would make "candidate"
  feel indistinguishable from "supported." D-031 requires a dated per-agent
  validation record, while the release-gate evidence pattern already provides a
  durable place for raw transcripts and provenance.
- **Decision**: Experimental adapters are built into committed `dist/` and
  bundled into the npm package, but `treenail install` and `treenail update`
  never install them by default. They require explicit `--experimental <agent>`
  opt-in and installer/detect output must label them unvalidated. Each
  experimental adapter first gets a dated, source-backed surface dossier in
  `docs/release-gate-evidence/` covering official docs/source links, install
  path, instruction/skill format, config directory, CLI/TUI/headless mode, and
  permission or sandbox behavior. Graduation to supported requires passing the
  D-031 parity run from the packaged install path using `--experimental
  <agent>`, with the validation record naming agent version, model/provider
  where applicable, channel, OS, and interaction mode. Public parity surfaces
  list only supported agents; experimental adapters may be documented separately
  as unvalidated opt-in adapters and must not appear in `SUPPORTED_AGENTS` or
  the README supported-agent table until they graduate.
- **Rationale**: Bundling candidates keeps validation honest because the same
  package a user would install is the package under test. Explicit
  `--experimental` preserves the support bar and prevents auto-detection from
  becoming an accidental endorsement. Dossiers keep raw surface facts out of the
  concise parity document until a candidate earns a public summary.
