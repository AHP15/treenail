## D-032: Enforce visible recommendation + rationale in the interview, even when a structured option list is rendered

- **Status**: accepted
- **Date**: 2026-07-08
- **Context**: D-028's factual basis is that the interview always surfaces the
  recommendation and its reasoning in prose before any tool renders. In
  practice this is inconsistent: the only place the rule lives is a soft
  sub-bullet at `challenge-me/SKILL.md:28` ("state your recommended answer and
  reasoning in 1-2 sentences, then ask if it works"), and when the agent jumps
  straight to a structured option list (Claude Code's `AskUserQuestion`) the
  "why this over the alternatives" prose can silently drop — the rationale gets
  compressed into terse option descriptions or omitted. A survey confirms
  `challenge-me` is currently the only skill with this recommendation-first
  interview loop, so there is no duplication to reconcile.
- **Decision**: Harden the instruction in place in `challenge-me` (step 5) into
  a hard rule: the recommended answer plus a 1-2 sentence rationale MUST appear
  in the chat as prose before or alongside every question; when a structured
  option list is also rendered, the prose rationale still appears — option
  descriptions do not count as the rationale; never surface a choice without a
  visible "why." No shared interview-protocol snippet is extracted yet
  (premature with a single consumer); revisit that only when a second
  interview-bearing skill appears.
- **Rationale**: The failure mode is specific and local, so a targeted wording
  fix in the one interview loop is the right-sized change; extracting a shared
  convention now would be indirection for a single consumer. Enforcing the
  visible rationale also repairs the empirical premise D-028 leans on, keeping
  that decision honest rather than aspirational.
- **Note (D-028)**: Child of D-028 — it strengthens, does not contradict, the
  reframe decision by making "the rationale is already shown in prose" reliably
  true instead of usually true.
