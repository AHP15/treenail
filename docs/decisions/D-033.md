## D-033: Experimental agent expansion starts as candidate runtime adapters, not supported agents

- **Status**: accepted
- **Date**: 2026-07-10
- **Context**: The next expansion targets Pi Coding Agent, Cursor, Kimi Code
  CLI, and Kiro. D-031 already gates the supported label on a dated parity
  validation record, and the latest retrospective warns that support claims are
  product systems with evidence, surface, and drift-guard costs. The requested
  names also mix runtimes and model brands unless the support boundary is made
  explicit.
- **Decision**: Treat Pi Coding Agent, Cursor, Kimi Code CLI, and Kiro as
  candidate agent-runtime adapters first. "Support" attaches to the agent
  harness/runtime, not to an underlying model provider, so Pi means Pi Coding
  Agent and Kimi means Kimi Code CLI rather than any tool using a Pi/Kimi model.
  Each candidate is implemented as a thin adapter from the existing canonical
  Claude-style `SKILL.md` source; no new canonical schema is introduced for this
  expansion. No candidate may be advertised as supported until it individually
  passes the D-031 support bar.
- **Rationale**: This keeps the expansion aligned with D-004/D-005 instead of
  forking the skill source or prematurely inventing a neutral schema. Candidate
  status lets Treenail discover runtime-specific instruction surfaces and
  interaction behavior without turning aspiration into a public promise. Naming
  support by runtime avoids the false equivalence between "model can code" and
  "Treenail works in this agent's install, context, and tool protocol."
