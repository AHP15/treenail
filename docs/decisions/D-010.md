## D-010: Updates overwrite Keel-managed dirs; per-project docs are never touched

- **Status**: accepted
- **Date**: 2026-07-02
- **Context**: `keel-skills update` must know what it owns. Users may edit installed skill files, and Keel copies CONVENTIONS-SPEC.md / CONVENTIONS-EXAMPLES.md into user projects' docs/ at adoption time, creating potential version skew.
- **Decision**: Provider skill dirs and ~/.keel are Keel-managed: update overwrites them wholesale, with the installed version stamped in ~/.keel/VERSION. Users customize by forking, not by editing installs. Per-project docs/ — including the conventions copies dropped into projects — are user data: updates never touch them, so each project's conventions stay frozen at adoption time.
- **Rationale**: Managed-overwrite is the only update model that stays simple and predictable in v1; three-way merging of user edits is installer complexity with a small audience. Freezing per-project conventions is deliberate: a project's records were written against the spec version it adopted, and silently upgrading the spec under existing records would corrupt their meaning.
