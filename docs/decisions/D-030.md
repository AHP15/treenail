## D-030: Public claim is functional parity plus a neutral surface note — not identical experience

- **Status**: accepted
- **Date**: 2026-07-08
- **Context**: Marketing Treenail as "equal support" (D-028) requires deciding
  what the public strings actually say. There is a hard honesty line: "full
  pipeline **fidelity** on all three agents" is true (the spike proves it),
  but "**identical experience** on all three" is false — Claude Code renders
  selectable options while Codex CLI and opencode use prose, a real,
  user-visible difference. The current surfaces (`README.md` "Per-agent
  support tiers", `site/content/docs/reference/agent-tiers.mdx`, and the site
  homepage) present a ranked Best/Full/Full tier table. Retrospective watch-for
  P6 warns to price new public strings up front.
- **Decision**: Claim **functional parity** — "Treenail runs the full pipeline
  on Claude Code, Codex CLI, and opencode." Drop the ranked Best/Full/Full
  tier column. Keep exactly one neutral sentence noting the surface difference
  (interview questions render as selectable options on Claude Code and as prose
  on the others — same protocol either way), stated as a fact, not a hierarchy.
  Do not claim identical UX; do not omit the surface note entirely.
- **Rationale**: Functional parity is the strongest claim that survives a user
  running two agents side by side. "Identical experience" is falsifiable in one
  session and spends credibility on our own docs; silent omission is a
  conspicuous gap a user will notice. The neutral surface note keeps the claim
  honest while still delivering the equal-support message.
