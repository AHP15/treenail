## D-023: Rename migration — reserve `treenail` on npm now; hard cutover, no old-name compat

- **Status**: superseded
- **Date**: 2026-07-04
- **Date superseded**: 2026-07-04
- **Superseded by**: D-024
- **Context**: The clean namespace that won Treenail the name (D-021) is perishable — `treenail` is only free on npm until someone claims it. Meanwhile `keel-skills@0.0.1` is already published as a placeholder, v1 has never shipped, and the only existing installs are the owner's own machines.
- **Decision**: Reserve `treenail` on npm immediately with a placeholder publish (mirroring the keel-skills reservation move). `keel-skills` stays published until Treenail v1 ships, then gets deprecated with a "renamed to treenail" pointer. The rename is a hard cutover: no `KEEL_HOME` fallback, no `~/.keel` migration shim, no plugin-name alias. Historical decision/risk/task records keep their "Keel" prose untouched — records are immutable history; only D-001 carries a superseded marker.
- **Rationale**: The npm reservation protects the one gate the rename made hard; losing the name would invalidate D-021's premise. Compat shims for an unshipped v1 with zero external users are pure debt. Rewriting historical records would falsify the project's own audit trail — the pipeline's records are append-only by design.
