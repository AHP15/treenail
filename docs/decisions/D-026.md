## D-026: Remove the `skills/_templates/` authoring scaffolds

- **Status**: accepted
- **Date**: 2026-07-04
- **Context**: `skills/_templates/` held `SKILL.template.md` + `FILL-GUIDE.md`
  scaffolds for authoring new interview-family skills (challenge-me,
  red-team-me). No skill body reads them at runtime; they are pure authoring
  convenience. The build ships them into `~/.treenail/templates/` and the
  installer symlinks them for Claude in `--dev`, so they carry real
  build/install/test coupling for zero go-forward use right now.
- **Decision**: Hard-delete `skills/_templates/` (`git rm`). Remove its build
  coupling — drop `_templates` from `build.py`'s `SUPPORT_DIRS`, delete the
  `_templates` reference-rewrite rules, and remove the templates walk in
  `build_treenail_home`; drop `_templates` from the `install.js` `--dev` Claude
  symlink loop and the `templates` asset check in `smoke-install.mjs`; rebuild
  the committed `dist/` trees. Git history is the recovery path if a new
  interview-family skill is authored later.
- **Rationale**: Nothing reads the scaffolds at runtime, so keeping dead files
  in-tree only pays maintenance and build-surface cost. The project's own
  principle is that durable prose lives in git history, so deletion loses
  nothing recoverable. An attic dir was rejected as a maintained path that
  build/install would have to keep ignoring.
- **Rationale (blast radius)**: Priced per the 2026-07-04 retrospective
  Pattern #1 — the removal is not "delete one dir" but touches `build.py`,
  `install.js`, the smoke test, and forces a `dist/` rebuild; all are in scope.
- **Note (D-006)**: Narrows what the shared `~/.treenail` runtime ships
  (no more `templates/`) but does not touch D-006's home-location or
  `TREENAIL_HOME` overridability, so it is not a supersession. Clean-replace
  provisioning (`replaceWithCopy` rms then copies) removes the stale
  `templates/` from installed runtimes on the next `install`/`update`.
