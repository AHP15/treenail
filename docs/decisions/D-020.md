## D-020: Node >=22 enforced by a startup version gate in the bin, not just advisory engines

- **Status**: accepted
- **Date**: 2026-07-03
- **Context**: D-017 set `engines: ">=22"` as advisory-only, reasoning that older Node fails with a legible loader error. R-016 disproved the premise: ESM parses fine on Node 18, npx runs despite the EBADENGINE warning, `help`/`detect` succeed, and only `install` crashes — with a raw `TypeError` from `path.join(undefined, …)` because `import.meta.dirname` is `undefined` below 20.11.
- **Decision**: Keep the `>=22` floor and `import.meta.dirname` (no shims). Add a version gate at the top of `main()` in `bin/keel-skills.js`: if `process.versions.node` major is below 22, print "keel-skills requires Node 22 or newer (you are running <version>)" and exit 1, before dispatching any subcommand. The `engines` field stays as declared metadata.
- **Rationale**: The gate is ~3 lines, runs on any Node that can parse ESM (12.20+), and converts a partial-function-then-cryptic-crash experience into one clear sentence — on exactly the machines (distro/corporate Node 18/20) an npx installer meets. Gating in `main()` rather than at import time works because the pre-22-breaking API is only *called* at run time, never at module load.
- **Supersedes**: D-017
