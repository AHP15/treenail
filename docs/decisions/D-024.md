## D-024: Rename migration — reserve `treenail` now, hard cutover, prose immutable but Evidence anchors maintained as live pointers

- **Status**: superseded
- **Date**: 2026-07-04
- **Date superseded**: 2026-07-04
- **Superseded by**: D-025
- **Context**: D-023 forbade touching historical records wholesale, but seven done tasks (T-004, T-011, T-018, T-019, T-020, T-030, T-031) carry machine-resolvable Evidence anchors that grep for keel-named strings and files; a hard-cutover rename dangles all of them, leaving `audit-artifacts`/`reconcile-status` flagging done work forever (R-022). The repo already practices anchor repointing (commit 0996a9d repointed T-026's Evidence when dist anchors went invisible), so the blanket immutability phrasing over-reached.
- **Decision**: All of D-023 stands unchanged — immediate `treenail` npm placeholder reservation, `keel-skills` deprecated with a pointer at v1, hard cutover with no `KEEL_HOME`/`~/.keel`/plugin-name compat — except the records policy, which is refined: historical record **prose** (Context, Decision, Rationale, Description, titles) is immutable, but **Evidence anchors are live pointers, not history** — when a rename or refactor moves their targets, anchors are repointed mechanically to the equivalent new path/string in the same edit that moves the target, preserving resolvability. Repointing changes where an anchor points, never what the task claims was done.
- **Rationale**: Evidence anchors exist to be machine-resolved against the current tree; an anchor that can no longer resolve documents nothing and poisons every future audit. Distinguishing pointer maintenance from history rewriting keeps the append-only principle meaningful instead of self-defeating, and matches what the project already does in practice.
- **Supersedes**: D-023
